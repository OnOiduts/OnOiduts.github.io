# 白板版说明（大白话）

## 这是什么

一个**文章、项目、介绍文字全部空掉**，但网站骨架、样式、播放器、部署配置全都在的版本。

用来干一件事：**先把 GitHub Pages 的部署流程跑通**，确认网址能打开、自动构建能变绿，再慢慢往里写东西。不用把还没写好的示例文章一起推上去。

打开之后你会看到：首页说「这里还没有文章」「这里还没有项目」，博客页和项目页是空的，关于页没有简介和演职人员。这是**正常的**，不是坏了。

## 和完整版的区别

| | 白板版（这个包） | 完整版 `onoiduts-site.zip` |
|---|---|---|
| 文章 | 0 篇 | 18 篇示例 |
| 项目 | 0 个 | 4 个示例 |
| 首页介绍 / 成员简介 | 留空 | 有文字 |
| 演职人员 / 友情链接 / 页脚随机字 | 清空 | 有文字 |
| 代码、样式、播放器、频谱、下载按钮、防护层 | **全都在，和完整版一模一样** | 同左 |
| 部署配置 `.github/workflows/deploy.yml` | 在 | 在 |

两份是**同一个站的两个状态**，别混着往一个仓库里推。想从白板切回完整内容，直接解压完整版覆盖即可。

## 部署 4 步（和完整版一样）

1. 在 GitHub 建一个**公开**仓库，名字必须是 `OnOiduts.github.io`（用户主页，网址没有子路径）。
2. 把解压出来的 `onoiduts/` 里的**所有文件**推上去：
   ```
   git init
   git remote add origin https://github.com/OnOiduts/OnOiduts.github.io.git
   git add .
   git commit -m "白板版，先跑通部署"
   git push -u origin master
   ```
   > 用 **GitHub Desktop** 的话：把解压出来的文件复制进仓库文件夹 → 填提交说明 → **Commit** → 顶部 **Push origin**。提交和推送是两下，只提交不推线上不会变。别漏了隐藏文件夹 `.github/`。
3. 仓库 → **Settings** → **Pages** → **Build and deployment** → **Source** 选 **GitHub Actions**（别选 "Deploy from a branch"，选错会打不开）。
4. 等 1～3 分钟，Actions 变绿，打开 `https://onoiduts.github.io`，`Ctrl+Shift+R` 刷一下。

看到首页的「这里还没有文章」就说明**部署成功了**。以后写新文章照常 `git add . → commit → push`，几分钟后自动更新。

> 仓库名必须叫 `OnOiduts.github.io`。如果换成别的名字，网址会多一层 `/仓库名/`，得同步把 `astro.config.mjs` 里的 `base: '/'` 改成 `base: '/仓库名'`，否则图片音频全 404。

## 怎么加第一篇文章

在 `src/content/articles/org/`（或 `buono/`、`zilan/`，对应三个成员）新建一个 `.md` 文件，比如 `first.md`：

```markdown
---
world: org
title: 我的第一篇文章
pubDate: 2026-11-21
tags: [随笔]
excerpt: 一句话简介，会显示在列表卡片上
pinned: false
kind: original
---

正文写在这里。可以用 Markdown 的全部写法。
```

**必填**：`world`、`title`、`pubDate`、`tags`（至少一个）、`excerpt`。
**可选**：`updated`、`cover`、`pinned`、`kind: original | reprint`、`source`、`sourceUrl`。

存好之后本地 `npm run dev`，首页和 `/blog` 就会冒出这篇。项目同理，放 `src/content/projects/`，字段见 `src/content.config.ts`。

播放器、相册、嵌入、单图说明这些指令在白板版里也都能用，例如：

```markdown
:::audio{src="/audio/sample.mid" title="练习曲"}
:::gallery
![图一](/covers/a-hello.svg)
![图二](/covers/a-md.svg)
:::
```

注意：**下载按钮默认是关的**。想让读者能下载某个资源，在指令里加 `dl="1"`，或者用写作台的「下载设置」勾选。

## 还留着哪些字

清空的是「你写的内容」。下面这些是**界面自带的文字**，不算文章，所以保留了，改起来也很直接：

- 导航上的「首页 / 博客 / 项目 / 关于」、页面标题、页头页脚结构
- 空状态提示（「这里还没有文章」之类）
- 三个世界的名字和配色（`src/data/identities.ts`）

想连这些也换掉，改对应组件即可，不影响构建。

## 还留着哪些文件

`public/` 下面有一批**示例媒体**（`audio/`、`videos/`、`covers/`），是给播放器和下载功能演示用的，不是文章。白板版没删，方便你部署后顺手验证播放链路。

想彻底干净就删掉这三个目录：
```
rm -rf public/audio public/videos public/covers
```
只留 `public/.nojekyll` 就行，页面照样能构建。

`docs/` 里留了部署说明、`测试指南.md`、`规则验证报告.md` 和这份说明，都不参与构建，删了也不影响网站。

## 两个小提醒

- **这个包现在带了 `package-lock.json`**，`deploy.yml` 里也写明了 `package-manager: npm`。两样都要推上去：官方 Astro Action 找不到锁文件会直接报 `No lockfile found` 失败。已经踩到这个红叉的话，看 `docs/部署到GitHubPages.md` 里的「最常见的红叉」一节，覆盖一个文件就能修。
- 本地想先看效果：`npm install` 然后 `npm run dev`。真要验证线上产物就 `npm run build`，生成 `dist/`。
