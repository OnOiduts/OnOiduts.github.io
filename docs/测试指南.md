## 零、Windows 一键启动（start.bat）

项目根目录有个 `start.bat`，**双击即可**，不用敲命令。它会依次：

1. 切到脚本所在目录
2. 检查 Node（要求 20 或更高）和 npm，没装会给出下载地址
3. 检查 `node_modules\astro`，没有就自动 `npm install`
4. 启动 `npm run dev`，并延时 6 秒自动打开浏览器

带参数用法（在资源管理器里不方便传参，可以开 cmd 到项目目录）：

| 命令 | 作用 |
|---|---|
| `start.bat` | 启动开发服务器（默认） |
| `start.bat build` | 构建静态站点，输出到 `dist\` |
| `start.bat install` | 重装依赖 |

装依赖时如果卡住或报错，多半是网络问题，改国内镜像：


### 网站搭建（演职人员表）

数据在 `src/data/credits.ts`，单列、居中，共 12 项。每项 = 角色 + 内容：

```ts
{ k: '代码', v: [{ text: '腾讯元宝', url: 'https://yuanbao.tencent.com' }, { text: ' Hy4 Preview' }] }
{ k: '构思', worldV: { org: 'OnOiduts工业', buono: '波萝Buono', zilan: '孜岚' } }
```

- 内容按段拆分，带 `url` 的段渲染成链接（强调色 + 加粗、新窗口），没 `url` 的是普通文字
- `worldV` 的项（「构思」）跟世界变：三个世界各渲染一份，由 CSS 按 `data-world` 显示，克隆体同步

行为（由 `ui.ts` 的 `initCredits` 接管）：

- 从下往上滚，**24 px/s**（300px 窗口约 12 秒一轮），改 `SPEED` 可调速
- **每次进入关于页都回到开场位置**：`reset()` 在初始化时调用；
  世界切换（`worldchange`）和 bfcache 恢复（`pageshow` persisted）也会归零重建 ——
  因为「构思」那一项跟世界变，停在中途会出现「上半屏旧世界、下半屏新世界」的错位
- 不记住上次的滚动位置
- 循环衔接：内容复制两份首尾相接，位移每满一份就减去该高度（取模）——
  下一份正好顶上来，不会「滚到底弹回顶部」
- **开场第一行在正中间**：`.credits-list` 顶部留 `padding-top: 150px`（= 半屏高），
  `openingOffset()` = `padTop - 窗口高/2` = 0。
  开场 offset=0，可视区上半是这段空白，第一行从正中开始往下排 ——
  上方干净，不会出现「框架」紧挨着「代码」（列表尾部）的情况。
  **只加顶部不加底部**：两份之间的间隔就只有 150px < 可视区 300px，
  滚动过程中任何时刻都还有内容可见，不会空屏。
  滚过之后 offset 取模回到 `[0, unit)`，进入常规无缝循环
- **字体加载完会重算**：`document.fonts.ready` 后重新 `build() + reset()` ——
  否则字体晚一步到位会改变行高（unit 变了），开场位置会偏约 12px
- **无边框、无圆角**：外层 `.credits` 只有 `position: relative` + `height: 300px` + 背景，
  连 `overflow: hidden` 都没有 —— 加了会形成裁切边界，视觉上又变回一个「框」
- **背景 = 黑色光斑**（垫在文字后面，向四周淡出，边缘融入页面）：

  ```css
  background: radial-gradient(ellipse 40% 130px at 50% 50%, rgba(0, 0, 0, 0.85) 0%, rgba(0, 0, 0, 0.72) 40%, transparent 100%);
  ```

  别写回 `ellipse at center` —— 默认 farthest-corner 会让 Rx≈764px、Ry≈212px，
  再乘 80% 的透明点，纵向 170px、横向 611px，几乎铺满整个容器。
  现在显式收窄：Rx = 40%×宽、Ry = 130px（与 mask 的 Ry 一致），
  实测覆盖范围约为原来的 35%。

  缩小的底线是「文字始终踩在黑底上」：内容最宽只到 ±154px，
  那里 t≈0.36 仍在 40% 的实心区内（实测 alpha 0.73），所以日间也不会出现浅底上的浅字。
  色标同样必须用百分比。
- 渐隐：**径向椭圆 mask**（在 `.credits-view` 上，`::before/::after` 线性遮罩已移除）

  ```css
  mask-image: radial-gradient(ellipse 80% 130px at 50% 50%, #000 40%, transparent 100%);
  ```

  ⚠️ **色标必须用百分比，绝不能用 px**：实测 Chrome 会把椭圆渐变里的 `<length>` 色标
  按「横轴半径」归一化 —— 写 `45px` 实际被当成 `45/972 ≈ 4.6%`，
  纵向在距中心仅约 27px 处就全透明了，正文几乎全被淡光（这曾是「文字看不见」的真因）。

  百分比直接对应归一化位置 `t = sqrt((dx/Rx)² + (dy/Ry)²)`，行为可预期：
  - `Rx = 80%×宽`、`Ry = 130px`
  - `#000 40%` → t ≤ 0.40 全清晰：纵向 ±52px（约 4 行）、横向 ±346px（内容只到 ±154px）
  - `transparent 100%` → t=1 全透明：纵向 dy=130px
  - `Ry` 取 130 而不是半高 150 是故意的：留 20px 余量，
    保证到容器上下边缘时一定已全透明，循环衔接不露馅

  注意 mask 只影响绘制、不影响命中测试，链接照常可点。
  验证脚本 `verify_credits.mjs` 会注入纯白铺满层、截图量像素来核对真实 alpha 分布，
  不再靠解析 CSS 字符串推算
- **文字用「深色底」配色**：整块坐在黑色光斑上，所以不能跟明暗走 ——
  角色名 `rgba(255,255,255,0.62)`、值 `#eeeeF2`、链接 `var(--accent-on-dark)`。
  `--accent-on-dark` 是每个世界单独定义的亮色版（组织 `#9dc2e8` / 波萝 `#b6ffa0` / 孜岚 `#dfb8ff`），
  日间版的 `--accent-text` 是深蓝/深绿/深紫，压在黑斑上等于隐形
- **容器必须裁切**：`overflow: hidden` + `overscroll-behavior: contain` + `touch-action: none`。
  轨道高约 800px，不裁就会溢出并把整个页面撑高（多出一大片可滚动区域）。
  裁切是安全的 —— mask 在距中心 150px 处已全透明，而容器半高正好 150px，
  被裁掉的部分本来就完全不可见，不会出现硬边。
  `overscroll-behavior: contain` 阻止滚到头后传递到外层；
  `touch-action: none` 让触摸端在这里滑动只翻滚内容、不被当成滚页面
- 区域固定 **300px**
- 按住可拖拽（跟手），松开按原速继续滚
- **不做鼠标悬停暂停** —— 想细看就按住拖着翻滚；滚动中链接依然可点
- 键盘 Tab 到链接时暂停（用 `:focus-visible` 区分，鼠标按下链接不会误触发暂停）
- 拖拽位移超过 6px 判定为拖拽，捕获阶段拦掉 `click`，拖完不会误跳转

### 友情链接：展开后是一片「宇宙」

**链接分布：网格分配，一格一个**（不是随机撒点）

```
cols = min(链接数, floor(可用宽 / (最宽链接 + 2×gap)))
cols = min(cols, ceil(sqrt(链接数 × 1.6)))   // 别让每行太矮，看着像列表
rows = ceil(链接数 / cols)
格子顺序打乱 → 每个链接随机占一格，格内再随机抖动
```

为什么不用「随机撒点 + 碰撞重试」：链接多的时候它会退化 —— 后来的链接找不到空位
就只能把区域越撑越高，而且容易出现「一边挤一堆、一边空一片」。
网格天然保证：① 一格最多一个 → 不可能重叠；② 每格都被用上 → 分布均匀；
③ 格内留 `gap/2` 边距，相邻格子的内容之间至少隔 `gap`，漂浮也不会撞上。

⚠️ **两个必踩的坑**：

1. `cellW = maxW + gap*2` 只是「放得下的最小格子」，只能用来算 cols；
   真正布局要用**均分后的** `colW = innerW / cols`、`rowH = availH / rows`。
   混用会导致链接少时列数被收窄、格子只占左边一小条 ——
   实测 6 个链接只铺到 x=426/1080，右边一半全空。
2. **不要用「横向跨度占比」当均匀性判据**：最右那列里的链接在格内随机抖动，
   落在格子左端时跨度是 53%、右端是 90%，同一份代码会偶发失败。
   要用「占用的列数 / 行数」，那是可推导的下界（n 个格子从 cols×rows 里选）。

装饰（星星 / 云朵）走**同一套网格**（edge 8、gap 12），所以同样是均匀散开的。
月亮 / 太阳**不参与网格**，仍然只放一个、固定在右上角内侧。

网格参数会写进 `dataset`（`data-cols` / `data-rows` / `data-edge`，
装饰是 `data-dcols` / `data-drows` / `data-dedge`），测试按同一套网格逐格校验。

**星云背景**：`#friend-glow`，一个绝对居中的椭圆。

```css
background: radial-gradient(closest-side ellipse,
    var(--friend-bg) 0%, var(--friend-bg) 62%, transparent 100%);
```

- **62% 之前都是实色，只有 62%→100% 渐隐到透明** —— 「中间实色，只在边缘渐隐」
- **大小由 JS 按内容算**：`w = min(W*0.99, H*1.6 + W*0.42)`、`h = H*0.98`
- **颜色 = 黑蓝，且跟世界变**：

```css
/* tokens.css 夜间段 */
--friend-bg: color-mix(in srgb,
    color-mix(in srgb,
        color-mix(in srgb, var(--accent) 26%, #0b2a5e) 32%,
        #050a1c) 88%,
    transparent);
```

  ⚠️ 三步混色是**必须的**。直接把 accent 混进深底，孜岚（紫 `#c77bff`）会把整块带紫：
  实测 `rgb(45,33,72)`，r 明显大于 g 就是紫。
  所以先让 accent 和一个钴蓝 `#0b2a5e` 混一次**去紫**，再混进近黑的深蓝底。
  结果三个世界都是 `b > g > r`：
  **组织 rgb(14,29,58) / 波萝 rgb(16,38,48) / 孜岚 rgb(23,27,63)**

**装饰**：夜间 **星星 ×N + 月亮 ×1**，日间 **云朵 ×N + 太阳 ×1**。
颜色走 `currentColor`（SVG 里写 `fill="currentColor"`），由 `--deco-small` /
`--deco-big` 给，明暗各一套。切主题会自动重建（`MutationObserver` 盯 `html[data-theme]`）。

**展开动画**：`.open` 触发高度 + 透明度过渡（.45s / .4s）；排版完成后加 `.is-laid`
触发逐个浮现（`friend-appear`，按 `--ad = i*45ms` 错开）；装饰 0.7s 淡入。

⚠️ `friend-appear` 必须用 `animation-fill-mode: backwards`，**不能用 `both`/`forwards`**
—— fill 会一直压着 transform，把 hover 的 `scale(1.18)` 一起压掉。
`open` 和 `is-laid` 必须分开：排版是 async 的（要等图片和字体），一点击就播浮现动画的话，
那时链接还在 `-9999px`。

**链接**：文字 14~24px 随机 / 图片大边 40~80px（`max-width` + `max-height` 都设 `--sz`，
配 `object-fit: contain`）。数据里带 `logo` 就是图片型：

```ts
{ name: '站名', url: 'https://...' }               // 文字
{ name: '站名', url: 'https://...', logo: '...' }  // 图片
```

悬停放大**必须挂在内层 `.friend-in`** —— 外层 `.friend-item` 的 transform 被漂浮动画
每帧占着，写在它身上不生效。发光用 `filter` 可以挂外层。

验证脚本 `verify_universe.mjs`（60 条）：网格逐格校验（链接 + 装饰）、列行覆盖、
最近邻间隙、三个世界都是蓝且不偏紫、椭圆尺寸随内容、展开过程逐帧采样。

### 三项打磨（网格变淡 / 加载态渐进 / 光晕改柔和波前）

**① 网格：调到「隐约的数据感」**
- 线色：正交 α 0.07 → **0.03**（日间 0.06 → 0.028），斜网格再砍一半（0.038 → **0.013**）
- 格子：60 → **84px**
- 斜网格格子再放大 1.6 倍（84 → **134px**），且线更淡 —— 原来和正交同尺寸同浓度，叠起来像格子布

**② 加载态：内容渐进出现**

原来 `#app` 只做 opacity 0→1，而网格是 `body` 的伪元素、HUD 是固定层，
**都不在 `#app` 里**，所以会先于内容出现 —— 看起来就是「背景先亮、内容突然冒出来」。

现在三者统一：状态挂在 `<html>.app-ready` 上（伪元素拿不到 class，只能这样）：
- `#app`：opacity 过渡
- 网格：`html:not(.app-ready) body::before/::after { opacity: 0 }`
- HUD：整块 opacity 0.8s，扫描线再延迟 0.35s（避免第一眼就看到一条线在扫）

`.app-ready` 由 `bootSequence` 的 `finish()` 加；导航跳过遮罩时由 head 的 inline script 直接加
（并配 `html[data-skip-boot]` 让三者立刻可用，不再等 0.7 秒淡入）。

⚠️⚠️ **`#app` 上绝不能留 transform**（哪怕是过渡结束后的 identity matrix）——
一旦有 transform，`#app` 就成为内部所有 `position: fixed` 的包含块：
1. 目录（`.toc`）会跟着页面滚，不再固定
2. 移动端浮层（`.mobile-panel`）会被算进文档宽度，撑出横向滚动
   （实测 `scrollWidth` 从 1440 变成 1760）
过渡结束后 computed 值是 `matrix(1,0,0,1,0,0)` 而不是 `none`，照样创建包含块。
所以「渐进出现」的位移感只做 opacity，位移交给卡片自己的 `.reveal`（它不在 fixed 元素上）。

**③ 光晕：从「一坨光炸开」改成「柔和波前」**

- **圆心 = 点击处**：`playBurst(origin)`，拿不到时退而求其次找 `.search-user-item`
- **柔化**：去掉白核、去掉 box-shadow（刺眼的来源就是它）、起始 `scale(.4)` 而不是 0，
  峰值 opacity 只有 0.55，单层细亮边当波前
- **波前驱动解码**：`glitchDecode` 现在按元素到波源的距离排 delay
  （`delay = 距离/对角线 × SPREAD`，SPREAD=0.55），近的先解、远的后解。
  总时长 900ms，波前用前 55% 扫过全屏，剩下 45% 让最后一批解完

⚠️⚠️ **解码必须在世界切换之后才启动**：
世界在 500ms 时才切（`switchWorld` 的 setTimeout），而切世界会重建文章列表 DOM ——
如果点击就立刻解码，500ms 后旧节点被整个换掉，新内容直接以明文出现，
「波前扫过、内容解码」根本看不见（实测 300ms 时只剩 1 个旧元素在解）。
现在放在 500ms 的回调里、再延后 90ms 等 React 渲染完才启动。

### 内容区羽化：拉长 + smoothstep（本轮）### 内容区羽化：拉长 + smoothstep（本轮）

   纯靠改曲线无法改变物理长度。代价是屏幕边缘 alpha 不再是 0（约 0.15），
   但叠在纯黑底 (#000) 上只有 **1.35 个色阶差**，肉眼不可见。想更平缓就调 1.3 这个系数
   （1.5 时残留约 2.6 色阶，开始可察觉）。
3. **裁剪层必须是 `main`，不是 `body`** —— 溢出从 `.container.page` 经 main 传播到 html，
   在 body 上 `overflow-x: clip` 实测无效（scrollWidth 仍是 1483 > 1440）。
   用 `clip` 而非 `hidden`：hidden 会创建滚动容器，且 clip **不创建包含块**，
   所以 `.toc` 的 `position: fixed` 不受影响。
4. **「无分界线」的判据要放在内容区边缘那一端，不是屏幕边缘** —— 屏幕边缘是视口物理边界，
   人眼不期待渐变；且羽化外扩后屏幕边对应曲线 t≈0.23 而非 t=0，那里斜率本就不为 0

- 字符解码：1000ms → **500ms**
- RGB 分离 + 横切错位条，**进入和回组织都有**（原来只有进入时有解码）

⚠️⚠️ **`.app-glitch` 里绝不能用 `transform` 或 `filter`** ——
两者都会给元素创建「包含块」，使其内部所有 `position: fixed` 变成相对该元素定位。
`#app` 里有导航栏（`.nav`）和目录（`.toc`）两个 fixed 元素，
实测一加 filter，切换那 0.5 秒导航栏就脱离视口顶部跟着滚走。
所以：
- 分离只走 `text-shadow`（可继承，纯绘制，不影响布局与包含块）
- 位移抖动交给独立的 fixed 覆盖层 `.glitch-bars`
- 内容块（`.card` / `.tl-items` / `.credits`，都不是 fixed）才用 transform 抖

**⑥ 加载态只在真正需要加载时显示**：
点导航链接 → `sessionStorage` 写 `onoiduts-skip-boot=1` →
下一页 head 的 inline script（`THEME_BOOTSTRAP`）读到后立刻给 `<html>` 加
`data-skip-boot` 并**清掉标记** → CSS `html[data-skip-boot] #boot { display: none }`。

⚠️ 标记必须在 head 的 inline script 里落，不能等 `bootSequence` ——
那时遮罩已经画出来了，会闪一下。
标记读完即清，所以真正刷新 / 新标签打开仍然正常显示加载态。
只认站内同源普通跳转：外链、锚点、`target != _self`、`download` 都不算。

### 首页 B 的点击锁（只播一次）
### 首页 B 的点击锁（只播一次）

锁在 `ui.ts` 的 `initB()` 里，三个要点缺一不可：

1. **模块级时间戳**，不是每个元素闭包里的布尔量。
   一旦 `initB` 被重复执行（或元素被换掉后重新绑定），
   每份闭包各有一个 `busy`，第 2 份监听器看到的是 `false`，锁就形同虚设。
2. **解锁只由时间戳决定**（`点击时刻 + 1000ms`）。
   `animationend` 只负责收尾 class、不再负责解锁 ——
   否则任何一个后代元素的其它动画结束（或某个部件时长被算成 0）都会提前把锁打开。
3. **事件委托绑在 document 上**，不绑在具体元素上。
   元素被重新渲染换掉后监听不会丢，也不会重复叠加（额外用 `window.__bInit` 幂等）。
4. **动画期间加 `.b-locked`（`pointer-events: none`）** —— 第二道保险。
   漂浮动画会让 B 缓慢移动，快速连点时某一次可能落在旧位置的元素碎片上。

**另外：世界切换后必须重新 `inkSvgB()` + `prepareBShatter()`。**
点 B 会切回组织，`worldchange` 之后 B 的 SVG 被重新渲染成**新的 DOM 节点**，
打在旧节点上的 `.b-ink` / `.b-part` 全没了 —— 不补的话切完世界 B 就
既不变色也散不开（`ui.ts` 里的 `refreshSvgB`，worldchange 后 620ms 执行）。

```ts
const B_LOCK_MS = 1000;
let bLockUntil = 0;
document.addEventListener('click', (e) => {
  const el = (e.target as Element)?.closest('[data-b-action]');
  if (!el) return;
  const now = performance.now();
  if (now < bLockUntil) return;      // 动画进行中：忽略
  bLockUntil = now + B_LOCK_MS;
  el.classList.remove('b-shatter');  // 强制重启动画
  void el.offsetWidth;
  el.classList.add('b-shatter');
  triggerB(el);
});
```

压力测试（`verify_click.mjs`）：真实鼠标 10 连点 →
动画启动次数 = 部件数（12/12，不是 120）；中途补点不新增；
解锁后能再播；第二轮 8 连点同样只播一次。

### B 点击：部件散开 + 只播一次的锁
### B 点击：部件散开 + 只播一次的锁

**动画**：各部件向四周飞散 + 渐隐，再飞回来拼回原样 + 渐入，总时长 1 秒。

方向由 JS 在运行时算（见 `ui.ts` 的 `prepareBShatter`）：
取每个部件中心相对 SVG 中心的方向，距离 = viewBox 宽度的 45%，
再错开起始时间（`--d`，最多 110ms）和旋转角度。
不管原稿有多少部件、什么结构都适用（顶层若只有一个 `<g>` 会往下钻一层）。

四个坑，全踩过：

1. **选择器必须写 `:global(.b-part)`**。`.b-part` 是 JS 运行时加到 SVG 内部元素上的，
   而 SVG 由 `set:html` 注入，注入的 children 不带 Astro 的 scope 属性
   （`data-astro-cid-*`）。不写 `:global` 会编译成 `.b-part[data-astro-cid-*]`，
   永远匹配不上 —— 表现为「点了没反应」。
2. **`--base` 不能写空字符串**。部件可能自带 SVG `transform` 属性，
   而 CSS transform 会整个盖掉它，所以要把静止时的 computed transform 存进 `--base`
   拼在关键帧最前面。没变换时若写 `--base: ''`，整条 transform 声明会失效
   （computed 变 `none`，部件完全不动）—— 要写成 `translate(0px, 0px)`。
3. **正好落在中心的部件**：dx/dy 都是 0，单位向量算不出来，会原地不动。
   改成按序号均匀分配方向。
4. **动画时长写成 `calc(1000ms - var(--d))`**：延迟 + 时长恒等于 1000ms，
   所有部件同时收尾，JS 才能用一个 `animationend` 解锁。

**「只播一次」的锁**（`initB`）：点击时置 `busy`，动画进行中的点击直接忽略；
`animationend` 冒泡上来时解锁（另有 1300ms 兜底定时器，防止动画没跑导致永久锁死）。
`b-shatter` 的加/删只由 `initB` 管 —— `triggerB` 里那份已经删掉，
两处各起一个定时器会把动画打断。

### 卡片辉光不能被裁成方块

卡片整体是 `<a>`，hover 时 `a:hover { text-shadow: 0 0 var(--glow-blur) var(--accent) }`
会继承给标题 / 日期 / 标签 / 摘要，光晕需要扩散到卡片边界**之外**才自然。

两处曾经会截断它，都已处理：

1. **`.card.pinned` 不能加 `overflow: hidden`**。
   它原本是为让图钉角标贴合右上角而加的，代价是把卡片内所有光晕切成直边。
   现在角标自己贴合：

   ```css
   .card.pinned::after {
     top: -1px; right: -1px;              /* 抵掉 1px 边框：absolute 基准是 padding box */
     border-radius: 0 var(--radius) 0 var(--radius);  /* 右上与卡片同圆心同半径，弧线重合 */
   }
   ```

2. **`.card-excerpt` 的 `overflow: hidden`**（单行 ellipsis 必需）也会切光晕。
   解法是给光晕留呼吸空间 —— padding 撑开、等量负 margin 拉回，
   文字视觉位置和卡片高度都不变：

   ```css
   .card-excerpt { padding: 10px 12px; margin: -2px -12px -10px; }
   ```

   垂直 10px 对应夜间 `--glow-blur: 14px`，到这里已衰减到约 15%，硬边基本看不出。

**内联带来的三个好处**（外链时做不到）：

2. **B 双色** —— 黑色部分 → 当前世界强调色，白色部分永远不动。
   **分色由 JS 在运行时按实测颜色判定**（`ui.ts` 的 `inkSvgB`），不是靠 CSS 猜 `fill` 属性值：
   - 判据：三通道都 ≤ 60 → 墨色，加 `.b-ink`，`fill: var(--accent) !important`

原稿尺寸多大多小都不会撑爆 —— 缩放靠 `preserveAspectRatio="xMidYMid meet"`（等比、居中、不变形）。

**viewBox 的处理**（`src/utils/svg.ts` 的 `normalizeSvg` + 客户端兜底）：

原稿常带写死的 `width="800"` 之类，或缺 `viewBox` —— 这两种情况下 CSS 的 `width:100%` 都不生效，图形会按原始像素渲染。处理顺序：

1. 有 `viewBox` → 直接用
2. 没有 → 用 `width`/`height` 的数值推断一个
3. 两个都没有 → 渲染后用 `getBBox()` 量出内容范围补上
4. 无论如何都会补 `preserveAspectRatio="xMidYMid meet"`，并**去掉写死的 width/height**（尺寸交给容器）

所以只要原稿是矢量图形，一般都能正常缩放。若原稿连 `width`/`height` 都没有且内容坐标为 0 起点，建议手动加 `viewBox` 更稳妥。

## 相册 :::gallery 与便签样式（新增功能）

### 用法

正文里写（文章页 / 项目页通用）：

```markdown
:::gallery
![第一版](/covers/site.svg)
![第二版](/covers/a-md.svg)
:::
```

单张插图不用包，直接写就行，会自动变成便签样式：

```markdown
![草图](/covers/a-song.svg)
```

### 实现要点

| 环节 | 位置 |
|---|---|
| 语法识别 | `src/plugins/remark-gallery.mjs`（remark 插件，产出 mdast html 节点） |
| 插件注册 | `astro.config.mjs` 的 `remarkPlugins: [remarkDirective, remarkGallery]` |
| 样式 | `global.css` 的 `.gallery-*` 与 `.prose p > img:not(.gallery-img)` |
| 交互 | `ui.ts` 的 `initGalleries()`（翻页 / 灯箱） |
| 配色 | `tokens.css` 的 `--note-bg` / `--note-shadow` / `--gallery-bg` |

⚠️ 四个坑：

1. **`remarkDirective` 必须排在 `remarkGallery` 前面** —— 否则 `:::gallery` 不会被解析成
   containerDirective 节点，会原样输出成字面量文本。
2. **指令名大小写敏感** —— 写 `:::Gallery` 不会命中（remark-directive 保留原始大小写）。
3. **`.gallery .gallery-img` 这个选择器不能简写成 `.gallery-img`** ——
   特异性 (0,1,0) 压不过 `.prose img` (0,1,1)，图片会多出一条 `--border` 描边。
4. **`--gdir` 动画重启要强制重排** —— 同一帧内 `remove` + `add` 浏览器会合并，
   CSS 动画不会重启（翻第二次就没动效了）。`void im.offsetWidth` 不能省。

### 首尾只显示一边小图

空缺那侧用 `.is-void`：**`visibility: hidden` 而不是 `display: none`**。
`display:none` 会让那一列塌掉，中间大图跟着往左/右跳，翻页时整块在抖。

### 依赖

## 原创 / 转载 + 视频播放器（新增功能）

### 原创 / 转载

文章 frontmatter 加三个字段：

```yaml
kind: reprint      # original（默认）| reprint
source: 某设计周刊  # 转载来源名，可省
sourceUrl: https://example.com/post   # 原文链接，可省
```

`kind` 有默认值 `original`，**老文章不写也能过**，不需要批量补。

显示位置：博客卡片、博客列表、首页最新文章、文章详情页（转载还带来源链接）。

### 视频播放器

```markdown
:::video{src="/videos/demo.mp4" title="标题"}
:::
```

也可以写成 `:::video` + 里面放图片或裸路径（和 gallery 同款）。

| 功能 | 实现 |
|---|---|
| 倍速 | 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 |
| 音量 | 0~100% + 静音切换 |
| 逐帧 | 按 1/fps 微调 `currentTime`，前后都能走 |
| 快进快退 | ±5 秒 |
| 截图 | canvas → 弹窗预览 → `showSaveFilePicker` 选位置保存 |
| 全屏 | `requestFullscreen` |
| 键盘 | 空格 播放/暂停，← → 快退快进，`,` `.` 逐帧 |

外链平台（B 站 / YouTube / Vimeo…）**不建播放器**，退化成外链卡片 —— 它们不给原始视频流，倍速和逐帧都会失效。

⚠️ 四个坑：

1. **逐帧的 fps 不能写死 30** —— 24/25/30/60 都很常见，写死会跳 1~2 帧。
   用 `requestVideoFrameCallback` 采样 `mediaTime` 差值取中位数（不支持则退回 30）。
2. **服务器必须支持 HTTP Range** —— 没有 Range 时 Chrome 拿不到分片，
   `video.currentTime` 赋值会被**静默忽略**（实测恒为 0，逐帧/快进退/进度条全失效）。
   GitHub Pages 支持；自建服务器要确认 `Accept-Ranges: bytes` 返回 206。
3. **截图弹窗的尺寸别用 `img.naturalWidth`** —— 图片刚插入 DOM 还没 load 完，读到 0。
   直接用 `video.videoWidth/Height`。
4. **`showSaveFilePicker` 必须在用户手势里调用**，不能提前 `await`，否则被浏览器拒绝。
   不支持的浏览器（Firefox/Safari）退回普通下载。

## 启动报错排查

### `Cannot find module 'remark-directive'`

这是缺依赖。相册和视频播放器用到两个包：

```bash
npm install remark-directive unist-util-visit
```

它们已经写进 `package.json` 的 dependencies，正常 `npm install` 会自动装上。
如果你之前装过旧版本的项目，直接再跑一次 `npm install` 即可补齐。

`start.bat` 会逐个检查依赖目录，缺哪个都会自动触发安装 —— 所以**重新双击
start.bat 就能自愈**，不需要手动敲命令。

如果 npm 报网络错误，改用国内镜像：

```bash
npm install --registry=https://registry.npmmirror.com
```

### 视频播放器不工作（进度条拖不动 / 逐帧没反应）

多半是服务器不支持 HTTP Range。GitHub Pages 支持；本地 `astro dev` 也支持。
自建服务器要确认响应头里有 `Accept-Ranges: bytes`、Range 请求返回 206。

### 端口 4321 打不开

端口被占用时 Astro 会自动换一个（比如 4322）。看黑窗口里实际显示的地址，
不要照抄本文档里的 4321。
